## 3. 실험 묶음별 해석

### A. 손실함수: 작지만 꾸준한 효과, 비용 없음
- `boundary`(경계 1px 이내 픽셀 가중) **+0.41**: 90장 중 62장에서 좋아져서 꽤 꾸준해요. Eutectic Si +0.83.
- `lovasz`(IoU 직접 최적화) **+0.38**.
- `classw`(약한 상 가중) +0.13: 잡음 수준이에요.
- 손실함수만 바꾸는 거라 **학습 시간이 늘지 않아요.** 조합 후보로 적합해요.

### D. Attention(scSE): 효과 없음
- **−0.09**: 잡음 수준이고, Al3Ni(−0.50)와 Eutectic Si(−0.50)는 오히려 떨어졌어요.
- 논문 3(MAM-UNet)의 Attention 효과가 이 데이터에서는 재현되지 않았어요. 보고서에는 "검증했지만 효과 없음"으로 쓸 수 있는 의미 있는 음성 결과예요.

### E. 인코더: ConvNeXt가 가장 좋고 효율적
- `convnext_t` **+0.73**: Al3Ni +0.72, Eutectic Si +1.11로 약한 두 상이 모두 올랐어요. fold당 11.4분으로 효율도 좋아요.
- `effb4` +0.49는 시간이 더 걸려요(15.9분). `r50` +0.41.
- 모든 인코더를 같은 학습률(3e-4)로 학습했어요. ConvNeXt는 보통 더 낮은 학습률이 맞아서 **조정하면 더 오를 여지**가 있어요.

### F. 구조: UNet++ 유망, SegFormer는 확실히 탈락
- `unetpp` **+0.61**: 개선 사진이 68/90으로 **가장 꾸준**하고, Eutectic Si도 +1.37로 가장 많이 올랐어요.
- `segformer` **−1.52**: Eutectic Si −2.40, Al −2.01로 가장 나빠요.
- 같은 인코더(MiT-B2)에 U-Net 디코더를 붙인 `unet_mit`은 +0.56이에요. 그래서 문제는 인코더가 아니라 **SegFormer 디코더가 1/4 해상도로 예측하는 방식**이에요. EDA의 해상도 상한 분석으로 세운 가설이 맞았어요.
- 보고서 활용: 논문 2(SegFormer 기반)의 방식은 가는 조직이 많은 이 데이터에는 맞지 않는다는 근거가 돼요.

### B. 해상도: '675px만 2배' 규칙 검증 완료, 무작정 키우는 건 효과 없음
- `noscale`(675px도 원본 그대로): 전체 −0.35, **675px 사진만 보면 76.2% vs 77.9%(−1.6%p)**. 지금의 2배 확대 규칙이 실제로 도움이 된다는 게 확인됐어요.
- `x2`(모든 사진 2배, crop 512) +0.21: 잡음 수준이고 Eutectic Si도 −0.07이에요. 해상도는 올랐지만, crop 하나가 보는 실제 영역이 1/4로 줄어서 이득이 상쇄된 것으로 보여요.
- `x2_c1024`(2배 + crop 1024, 기준 모델과 같은 실제 영역) **+0.75로 1위**.
- 하지만 같은 1024 crop을 원본 해상도로 쓴 `c1024`가 +0.43이에요. 그래서 **해상도 자체의 순수 효과는 약 +0.3%p**이고, 비용은 학습 3.8배, 예측 4배예요.

### C. 패치 크기: 약간 도움
- `c768` +0.48, `c1024` +0.43. 맥락이 넓어지는 효과는 있지만 768과 1024 사이에 차이가 없어요.
- 시간은 768이 2.1배, 1024가 3.5배예요. 쓴다면 **768이 효율적**이에요.

## 4. 자기 점검

**① 기준 모델(시드 0)이 운이 나빴어요. 그래서 비교 기준을 바꿨어요.**
- 처음 집계에서는 거의 모든 실험이 Primary Si에서 +1~1.6%p 좋아 보였어요.
- 추적해 보니 원인은 사진 한 장(`A181_step4_sample4`)이었어요. 기준 모델은 이 사진의 큰 Primary Si 덩어리를 19.8%만 맞혔고, 다른 실험들은 중앙값 97.2%를 맞혔어요.
- 그래서 기준을 **시드 0·1 두 모델의 평균**으로 바꿨어요. 그 결과 모든 Δ가 처음 집계보다 약 0.18%p 작아졌어요.
- **교훈:** 큰 덩어리 하나를 통째로 틀리는 사고가 가끔 일어나요. 이런 사고는 **앙상블로 줄일 수 있어요.**

**② 효과 크기가 잡음과 비슷한 수준이에요.**
- 시드 차이(0.35%p)를 보면 단일 실험 하나는 ±0.2%p쯤 흔들려요.
- 95% 구간이 0을 넘는 실험이 많지만, 이 구간에는 학습할 때의 운이 들어 있지 않아요.
- 그래서 +0.4%p 수준(`boundary`, `r50`, `lovasz`)은 **"아마도 좋음"**으로만 판단했어요. 확실하다고 볼 수 있는 건 +0.6%p 이상이면서 개선 사진이 60장 이상인 `x2_c1024`, `convnext_t`, `unetpp`예요.

**③ 여러 개를 동시에 비교한 효과**
- 15개 변형을 비교했기 때문에, 그중 1개 정도는 우연만으로도 "의미 있어 보이는" 결과가 나올 수 있어요.
- 그래서 다음 단계에서 **조합했을 때도 효과가 유지되는지** 다시 확인해야 해요.

**④ 중간 결과는 믿으면 안 돼요.**
- `lovasz`는 fold 2개만 끝났을 때 +1.31이었는데, 다 끝나니 +0.38이었어요.

**⑤ 실험 설계의 한계**
- 패치 크기 실험은 "주변 맥락"과 "한 번에 보는 픽셀 수"가 섞여 있어요.
- 인코더별로 학습률을 맞추지 않았어요.
- 무거운 작업을 맨 뒤에 배치해서 마지막에 GPU가 놀았어요(약 20~30분 손해). **다음 라운드부터는 무거운 작업부터** 배치할게요.

**⑥ 후처리 점검**
- 후처리가 진짜 Primary Si를 지운 경우는 85회 학습 전체에서 **0건**이었어요.
- 효과는 +0.04~0.25%p로 작지만 해가 없어서 유지해요.
- 기준값을 90장 정답 통계로 정한 약한 정보 누출은 남아 있어요. 효과가 작아서 결론에는 영향이 없어요.

**⑦ "평가 예상" 점수의 가정**
- 저대비 60% / 고대비 40% 가중은 평가 10장의 구성만 반영한 거예요.
- 평가 사진이 10장뿐이라 실제 점수는 ±2~3%p 달라질 수 있어요.

**⑧ 처음 기대치를 수정해요.**
- 처음에 "현실적으로 81~83%"라고 했는데, 단일 변경 효과가 최대 +0.75%p였어요.
- 조합, 앙상블, 90장 전체 학습까지 반영하면 **80~81%가 현실적**이고, 82%는 도전 목표예요.

## 5. 결정

| 구분 | 항목 | 이유 |
|---|---|---|
| **채택 후보** | ConvNeXt 인코더 | 가장 좋은 단일 변경이고 효율적이에요 |
| | UNet++ 구조 | 가장 꾸준하고 Eutectic Si 개선이 가장 커요 |
| | 경계 가중 손실(`--bw 2`) | 비용 없이 꾸준한 효과 |
| | crop 768 | 맥락 효과, 1024보다 효율적 |
| **유지** | 675px 2배 확대, TTA, Primary Si 후처리 | 이번에 효과가 검증됐어요 |
| **보류** | `x2_c1024` | 1위지만 비용이 3.8배. 조합 실험 뒤 여유가 있으면 검토 |
| | EfficientNet-B4, MiT-B2(U-Net) | 앙상블 다양성용 후보 |
| | Lovász 손실 | 경계 가중과 겹칠 수 있어서 조합으로 확인 |
| **제외** | SegFormer, scSE, 상별 가중, `x2`(crop 512) | 효과 없거나 나빠요 |

**참고:** UNet++ + ConvNeXt 조합은 현재 라이브러리(smp 0.5)에서 오류가 나요. ConvNeXt가 첫 단계에서 해상도를 1/4로 한 번에 줄여서 UNet++ 디코더와 맞지 않아요. 대신 쓸 수 있는 조합은 세 가지예요.
- UNet++ + ResNet50 또는 EfficientNet
- U-Net + ConvNeXt(+ 경계 가중 + crop 768)
- 둘 다 학습해서 앙상블
