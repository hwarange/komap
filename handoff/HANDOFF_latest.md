- 알루미늄 합금 광학현미경(OM) 사진을 4개 상으로 분할해요: Al(갈색), Al3Ni(파랑), Primary Si(초록), Eutectic Si(흰색 `(204,204,204)`).
- 평가는 이미지별 4개 상 mIoU의 평균이에요(평가 10장, 그중 6장은 학습에 없는 새 합금). 참고 기준은 75%예요.
- 심사(100점): 과제이해 5, 데이터처리 15, **모델정확도 50**, 인사이트 10, 독창성 20
- 규칙:
  - 없는 상은 제외하거나 100%로 처리
  - 외부 사전학습 가중치 사용 가능
  - 검증 데이터 학습 사용 가능
  - **평가 이미지를 학습에 쓰지 않음**
  - 제출은 4색 RGB PNG

## 2. 성능 흐름 (90장 합금 단위 5-fold, TTA + 후처리)

| 단계 | 내용 | CV mIoU |
|---|---|---|
| 기준 | U-Net + ResNet34 | 78.31 |
| sub1 | 12개 실험 앙상블 | 79.73 |
| sub2 | 16개 + Si 분류기 | 79.96 |
| sub3a | 25개 + Si 분류기 | 80.02 |
| sub4 | 25개 + Eutectic Si 전용 모델 30% + Si 분류기 | 약 80.10 |
| 최고 단일 모델 | `x2_unetpp_bw_e120_r90` (2배 해상도 UNet++ 120에폭, 시드 3개 79.95~80.03) | 80.03 |
| **sub5 (지금 최선)** | 27개 + Eutectic Si 전용 2개(0.4) + Al3Ni 전용(0.3) + Si 분류기 | **80.233** |
| 12단계 최선 후보 | + 시드 2 또는 3배 + Eutectic Si 전용 4개 | 80.325 (+0.09, 교체 안 함) |

- **상별 IoU (sub5):** Al 93.2, Primary Si 89.3, Al3Ni 79.4, **Eutectic Si 59.7**
- **남은 벽:** 경계 라벨 애매함이에요.
  - 경계 1px 제외 시 88.0
  - 학습한 사진에서도 82점
  - 정답을 1px 두껍게 그리면 Eutectic Si 62.3

## 3. 환경
| | 노트북 | 서버 |
|---|---|---|
| GPU | 쓰지 않음 | **L40S × 4** (46GB), 128코어, 1TB RAM |
| 파이썬 | 가상환경 `Komap` (uv, 3.13) | `~/komap/.venv` (uv, 3.12, torch 2.14.1+cu126, smp 0.5.0, timm 1.0.30) |

- **서버에만 있는 것:** 모델 가중치(`runs/cv`, `runs/full`), OOF 확률(`runs/oof/<실험>`), 앙상블 캐시(`runs/oof/_ens_*`), Si 분류기(`runs/si_clf/*.pkl`), 평가 사진 모델별 예측(`submissions/sub3_pred/parts`), 오답 지도(`runs/hardmaps`)
- **코드 동기화:** `scp <파일> komap:komap/<같은 경로>`로 보내요. 보낸 뒤 `md5sum`으로 같은지 확인해요.
  - 서버는 깃 저장소가 아니에요.
  - **실행 중인 bash 스크립트 파일은 고치지 마세요.** 지금은 `scripts/run_round13.sh`가 실행 중이에요.
  - 서버의 오래된 파일 일부는 줄바꿈이 CRLF예요(내용은 같음). 그래서 md5가 다르면 `diff --strip-trailing-cr`로 확인하세요.
- **결과 가져오기:** `ssh komap 'cd ~/komap && tar czf - <json·txt·log 경로>' > x.tgz`. `npy`·`pt`는 빼요.
  - Windows git bash에서 `tar`에 `C:/...` 경로를 주면 원격 주소로 오해해요. `/c/...` 경로를 쓰세요.
- **GPU 메모리** (`gpu_mem_gb` 기준):
  - 2배 해상도 UNet++/ConvNeXt는 약 14~15GB(조각 1024)라 GPU당 2개까지 돌릴 수 있어요.
  - **3배 해상도(27GB)와 2배 해상도 MiT(26.6GB)는 GPU 한 장에 하나만** 돌려요.
  - `launch.py --heavy <실험들>`을 쓰면 무거운 실험은 GPU를 통째로 쓰고, 빈 칸에는 가벼운 작업을 채워 넣어요.
- **CPU:** Si 분류기(HistGradientBoosting)는 기본으로 **코어 128개를 다 써요.** 여러 개를 동시에 돌릴 때는 `OMP_NUM_THREADS`(예: 20~32)로 제한하세요(10/8 부하 717 사고).
- 서버 홈에 다른 사람 파일이 있으니 `~/komap`만 쓰세요. GPU 4장 사용은 허락받았어요.

## 4. 코드 구조 (`src/`)

| 파일 | 역할 |
|---|---|
| `data.py` | 로딩, 정규화, 배율 규칙, 증강. 옵션: `elastic`, `cutout`(IGNORE=255), `hard`(오답 위치 중심 자르기), `feats`(3채널 필터 입력) |
| `infer.py` | 슬라이딩 예측, 8방향 TTA, 원본 해상도 복원(정수가 아닌 배율은 bilinear), IoU, Primary Si 후처리 |
| `train.py` | 학습. **새 옵션을 끄면 이전과 출력이 같아요.** 외부 사전학습용 `--init`, `--init-skip-head`, `--use-ignore` |
| `launch.py` | 실험 목록을 fold 작업으로 펼쳐 GPU에 배치. `--gpus 3 3 2 --per-gpu 1`처럼 칸 수 조절. **`--heavy`**(10/8 추가): GPU 한 장을 통째로 쓰는 실험 |
| `review.py` | 실험 하나를 기준과 같은 사진끼리 비교 + 이상 징후 점검 |
| `ensemble.py` | OOF 앙상블 평가 (전체 평균, 점수순 top-k, 탐욕적 선택 + 중첩 검증). 한 프로세스라 실험 29개에 약 1시간 |
| `si_classifier.py` | Si 덩어리 분류기 (`cv` / `fit`) |
| `decision_rules.py` | OOF 판정 규칙: `cache`, `bias`, `sie`(`--cls`, `--spec` 여러 개면 평균), `blendcache`. 모두 중첩 검증 |
| `check_full.py` | 90장 모델 안전 점검 (`train-score`, `agree`, `diff`) |
| `verify_cv_blend.py` | 섞기 포함 제출 코드 90장 검증 (`--ens` 여러 폴더, `--sie`, `--al3ni` 여러 폴더) |
| `submit.py` | 제출 예측. 평가 사진은 모델별로 저장(`predict`), `combine`에서 `--recipe`, `--full-mix`, `--sie-spec`/`--sie-alpha`, `--al3ni-spec`/`--al3ni-alpha`, `--si-clf` |
| `make_external.py`, `report_analysis.py` | 외부 데이터 변환 / 보고서 분석(상 분율, 탄성률, step 비교) |

## 7. 알려진 함정
- **문자열 치환으로 코드를 고치면, 맞는 문자열이 없을 때 아무 경고 없이 넘어가요.** `assert s.count(a) == 1`로 확인하고, 고친 뒤 실제 명령 경로까지 시험하세요.
- 서버 작업을 기다릴 때 `while pgrep -f "..."`를 쓰지 마세요. 자기 자신과 일치해서 끝나지 않아요. `pkill -f`도 자기 ssh 세션을 죽여요.
  - **done 파일이 생기는 걸 기준으로 기다리세요.**
  - 프로세스를 멈출 때는 `ps -eo pid,args | grep "[s]i_classifier.py"`처럼 대괄호를 쓰고, 고른 PID만 `kill`하세요.
- 서버 기본 셸은 `sh`예요. 배열은 bash 스크립트 안에서만 쓰세요. `cd ~/komap && A & B`처럼 쓰면 `&` 때문에 B가 다른 폴더에서 실행돼요.
- **CPU 작업 여러 개를 동시에 띄우기 전에, 각자 몇 코어를 쓰는지 확인하세요.** HistGradientBoosting과 numpy는 기본으로 전부 써요.
- UNet++ + `tu-convnext_*`는 smp 0.5에서 생성 오류가 나요.
- 모듈 이름 `half`는 `nn.Module.half()`와 충돌해요.
- numpy의 참/거짓 값은 JSON으로 저장할 수 없어요 → `bool()`로 바꾸세요.
- 고르는 과정이 있는 것(앙상블 구성, 섞는 비율, 비중)은 **중첩 검증**으로만 정직한 추정을 내세요. 중간 fold 결과로 판단하지 마세요.
- `ensemble.py`는 결과를 마지막에 한꺼번에 써서, 도는 동안 로그가 비어 있어요(정상).

## 8. 사용자 선호
- **항상 한국어로, 쉽게 설명해 주세요.** 어려운 개념은 그림이나 예시로 설명하면 좋아요(예: 돋보기 vs 똑똑한 눈).
- 실험마다 **왜 골랐는지 + 결과 + 버그 점검 + 놓친 점**을 보고해요. 실험 하나가 끝날 때마다 바로 보고해요.
- 계획을 먼저 보여주고 사용자가 정해요. "다 해 보자", "돌리자"라고 하면 바로 진행해요.
- 사용자는 아이디어를 많이 내고 질문도 많이 해요(예: "큰 모델은 뭐야?", "ViT는 별로야?").
  - **이미 시험한 것과 겹치는지 기록으로 확인하고, 근거와 함께 솔직하게 판단해 주세요.**
  - 나눈 논의도 `reports/idea_journey.md`에 기록해요.
- 거짓 음성을 조심해요. 설정 문제로 실패했을 수 있으면 다른 설정으로 다시 시험하고, 앙상블 재료는 앙상블 기여로 판단해요.
- 학습은 서버(L40S)에서만 해요. **남는 자원이 있으면 기다리지 말고 병렬로 돌리길 원해요**("더 빠르게는 못해?"). 다만 공용 서버 부하는 조심하세요.
- **작업이 끝나면 알림을 보내 주세요**(PushNotification). 결과는 늦지 않게 바로 보고해요.
- 인수인계 파일은 사본 없이 이 파일 하나로, 요청할 때만 고쳐요.
- 깃으로 관리해요. 단계가 끝나거나 제출본을 만들면 커밋하고 올려요.
